# One AI Key: Continue Grows, Selection Opens a Menu

Date: 2026-09-24
Status: approved direction (Figma "Iliad — AI writing interactions", option C); implementation spec
Scope: Autocomplete length model, keyboard model, selection AI actions, and the Writing assists menu.

## Reviewer brief

Review for: interaction consistency, safety of accept paths (no model text is
written without an explicit accept), stale-request handling during
escalation, keymap precedence between autocomplete and selection features, and
preference migration. The design is fixed by the owner; challenge the
implementation, not the direction.

## Problem

Autocomplete grew three manual lengths with three unrelated shortcuts
(Ctrl+Space phrase, ⌘↵ sentence, ⌘⇧↵ paragraph), plus Example/Transition/Tension
buttons and a "Continue with…" field inside the Writing assists menu. The owner
found them hard to learn ("not a keystroke progression"), and the menu mixes
in-the-moment actions with permanent settings. Selected text has a separate bar
(Comment · Tighten · Edit) with a second shortcut system (⌘⇧J). It is not clear
when the AI writes something new vs. rewrites.

## Product intent

One rule: **your selection decides.**

- Nothing selected → the AI writes NEW text at the cursor. It never changes
  existing words.
- Text selected → the AI CHANGES that text. It never continues past it. The
  change is reviewed in place before it is saved.

One key: **⌘↵ = "AI, help here".**

- No selection: ⌘↵ suggests a Sentence. Pressing ⌘↵ again while the suggestion
  is visible extends the same suggestion to a Paragraph, and again to the full
  Idea (until the current idea/section is complete).
- Selection: ⌘↵ opens a small AI menu for the selection.

One set of review keys everywhere: Tab accepts, Esc dismisses/rejects.

## Goals

1. Manual continuation lengths: `sentence` → `paragraph` → `idea`, driven by
   repeated presses of a single configurable key (default `Mod-Enter`).
   Automatic suggestions stay `inline` (short phrase) and are never paragraphs.
2. Escalation keeps the visible text and asks the model to continue it; the new
   ghost is `shown + extension`. Accepting inserts exactly what is visible.
3. Suggestion toolbar: Accept (Tab) · Longer (⌘↵, hidden at Idea) · Another ·
   ‹ n/m › · Steer… · ✕. Steer opens a one-line direction field that
   regenerates the current length with that direction.
4. ⌥↓ shows the next cached alternative or requests a new one; ⌥↑ goes back.
5. Remove "accept one word" (⌥→) and the phrase/paragraph shortcuts.
6. Selection bar becomes `Comment · ✦ AI ⌘↵`. The AI menu has a free-text
   instruction field on top and presets: Rewrite, Expand, Shorten, Summarize,
   Turn into a list. ↑/↓ + Enter picks a preset when the field is empty; Enter
   with text submits the typed instruction. Esc closes.
7. Shorten runs the existing Tighten mode; the other presets run the existing
   Edit mode with a canned instruction. Output goes through the existing inline
   review (unchanged safety checks). Tab accepts that review; Esc rejects.
8. Writing assists menu keeps settings only: Corrector, Autocomplete,
   "Suggest while I type" (switch; off = manual only), Pause for 10 min,
   Writing notes, Shortcuts & accessibility (one key selector, reference rows,
   Reset, Announce), API fallback.

## Non-goals

- No new provider work. Selection edits keep the Codex/OpenAI route; Gemini
  stays autocomplete-only (backlog).
- No "another"/Steer for selection rewrites in this pass (backlog).
- No paragraph-by-paragraph accept.
- No change to comments, the review diff renderer, or tighten safety ranges.

## Design

### Continue (renderer: `src/editor/ideaAutocomplete/`)

- `IdeaAutocompleteSuggestionKind = "inline" | "sentence" | "paragraph" | "idea"`.
- `AutocompletePreferences.shortcuts` becomes `{ continue: string }`.
  `normalizeAutocompletePreferences` migrates: use `shortcuts.continue` if valid,
  else the old `shortcuts.sentence` if valid, else `Mod-Enter`.
  Choices: `Mod-Enter`, `Mod-Alt-Enter`, `Alt-Enter`, `Mod-Shift-Enter`,
  `Mod-Shift-Space`, `Ctrl-Space`.
- The continue key handler:
  - selection non-empty → the selection keymap (registered first) opens the AI
    menu and always consumes the key; autocomplete also consumes it without
    acting, so the AI key never reaches `insertBlankLine` over a selection.
  - a suggestion is visible and not streaming → escalate to the next kind
    (`inline→sentence→paragraph→idea`); at `idea` swallow the key (no-op).
  - a request is in flight → swallow (no double requests).
  - otherwise → request `sentence`.
- Escalation request: model `prefix` = doc prefix + visible insert (trimmed from
  the front to `AUTOCOMPLETE_MAX_PREFIX_CHARS`), `extend: true`. The plugin keeps
  `base = visible insert`; partial and final results render `base + insert`.
  Stale checks keep comparing the *document* context captured at request time
  (cursor, doc prefix, doc suffix) — unchanged from today. Any edit, cursor move,
  focus loss, Esc, or composition cancels the request and clears the ghost.
- Variants: cached per (doc context, kind, direction, base). Escalated
  suggestions are one variant; "Another" regenerates the current kind from the
  document cursor (drops the base) so alternatives are comparable.
- Steer: toolbar button toggles an inline input; Enter calls
  `triggerManual(currentKind, direction)` which regenerates from the document
  cursor with the direction; Esc closes the input and refocuses the editor.

### Prompts and cleaning (main: `electron/agent/autocomplete.ts`)

- `idea` instructions: continue until the current idea is complete — normally
  the rest of the current section; may use several paragraphs and list items;
  at most ~4 paragraphs / 350 words; never write headings; stop before content
  that already follows the cursor and never repeat it.
- `extend` flag (`sentence`/`paragraph`/`idea`): "the text before the cursor
  ends with an unaccepted draft; continue directly from it". For `paragraph`
  extend, continue the same paragraph (no new paragraph).
- Cleaner: `idea` allows blank lines and list items, rejects code fences and
  any line that is a heading, max 2400 chars. Extended output uses
  `normalizeInsertionBoundary` against the model prefix (continuing inline);
  non-extended `idea` uses the paragraph boundary logic.
- Token budgets: OpenAI `idea` 700; Gemini `idea` 4096 (thinking shares the
  budget). IPC accepts `idea` and `extend`.

### Selection AI menu (renderer: `src/editor/selectionComments/overlay.tsx`)

- The floating bar renders Comment and `✦ AI` (with the continue-key hint).
  `✦ AI` opens the AI menu (the existing edit composer, extended), anchored to
  the selection. Disabled over the size cap, as Tighten/Edit are today.
- `handleAiMenuShortcut(view)` (bound to the continue key in
  `selectionCommentsExtension`) opens the menu for a non-empty, safe selection.
  Mod-Shift-J remains a hidden Tighten shortcut for existing users.
- Presets map to `{ mode: "tighten" }` (Shorten) or `{ mode: "edit",
  instruction }` with localized canned instructions. Typed instructions and
  presets are all selection-scoped (the old whole-unit scope heuristic is no
  longer used by the menu); the safe unit is context only.
- Tab accepts an active inline tighten/edit review (new keymap entry, active only
  while that review exists); Esc rejection is unchanged.

### Writing assists menu (`src/components/WritingAssistsMenu.tsx`)

Remove Phrase/Sentence/Paragraph, Example/Transition/Tension, and the direction
field; replace Automatic/On demand with a switch; shortcuts section shows one
selectable key ("Continue · AI menu"), then fixed rows for Accept (Tab),
Another (⌥↑/↓), Dismiss (Esc). `onAutocompleteAction` is removed from the menu.

## Tests

- Preferences migration (old three-key prefs → `continue`; invalid → default).
- Escalation: sentence visible + key → paragraph request with `extend`, model
  prefix includes visible text, final ghost = base + extension; idea swallows;
  doc edit mid-escalation cancels and clears.
- Key with selection returns false from autocomplete.
- Cleaner: idea multi-paragraph accepted, heading rejected, extend boundary.
- Instructions contain idea/extend wording; IPC normalizes `idea` and `extend`.
- Existing lifecycle tests updated for removed keys.

## Risks

- Extension quality: the model may restate the draft. Mitigated by
  `removeEchoedPrefix` against the model prefix.
- Idea length on slow providers: Idea gets a 30 s timeout (other lengths 18 s);
  streaming (Gemini) shows progress.
- Mod-Enter collisions: CodeMirror's default keymap binds Mod-Enter to
  `insertBlankLine`; our handlers run at higher precedence and return false only
  when they do nothing, preserving the default.

## Review log

- v1: Codex (gpt-6-sol, high) — NO-GO with 2 P0 / 5 P1:
  multiline ghost preview; menu actions must be selection-only (the Edit
  scope heuristic could widen to the whole unit); Mod-Enter needs an owner in
  every state; Tab precedence review → ghost → indent; escalation must keep
  the base through failures; contracts/variant key; Shorten minimum and menu
  key propagation. All adopted: ghost `white-space: pre-wrap`; every menu
  action uses the selection range; the selection keymap always consumes the AI
  key over a selection and autocomplete also refuses to act on one; Tab is
  bound in the selection keymap for the inline review; failed extensions keep
  the draft; Shorten is disabled below `minChars`; menu/steer inputs stop key
  propagation.
- Implementation pass 2: Codex — NO-GO with 1 P1 / 3 P2: ghost widget must
  report `lineBreaks`; variant key must include the extension base; a failed
  extension must restore `shown` (keeping the toolbar); preference migration
  must validate `continue` before falling back to `sentence`. All fixed with
  tests.
- Revision after owner testing (same day): stepping ⌘↵ three times was slow
  (three requests, two waits) and quick repeats were swallowed while a request
  ran. Added direct, configurable length keys — defaults ⌘, (Sentence),
  ⌘. (Paragraph), ⌘/ (Idea), neighbours on an English keyboard — each one
  request; a visible shorter suggestion is extended, and a key for a different
  length mid-request cancels and switches instead of waiting. ⌘↵ keeps its role
  (sentence + repeat to extend; AI menu on a selection). Preferences hold four
  distinct keys; older maps migrate their main key to the AI key.
